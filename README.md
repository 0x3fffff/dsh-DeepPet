# dsh-deep-pet

一个 DeepSeek Harness（DSH）桌宠插件。桌宠是一个无边框、透明、置顶的悬浮窗口：

![桌宠在 DSH 跑任务时的样子](https://img.cdn1.vip/i/6a8c5d86ac643_1787583878.webp)

- **拖动**：按下并左右拖动时播放 8 帧跑步动画，水平方向决定朝向（左=原帧朝左，右=水平镜像朝右；纯垂直拖动按朝左），松手停在原地并记住位置。
- **空闲**：默认 `平常.webp` 静态图，每隔 25～70 秒随机播一段待机动作（不连播同一个），播完回静态。
- **工作中**：DSH 开始跑任务时先播「开始打字」入场，播完接「持续打字」循环。进入有 800ms 防抖——半秒就结束的任务不该闪一下入场再跳走。
- **任务进度**：间歇式气泡，取自真实数据（`todo/write` 的 `in_progress` 优先，`tool/call` 兜底），显示 3 秒后消失、静默 1.5 秒，不常驻占屏。**不播音效**。
- **长时间无操作**：系统级空闲超过 5 分钟后播「打瞌睡 / 玩手机」并循环，60～120 秒换一个；一有输入立刻醒。
- **屏幕边缘**：拖到左/右边缘 24 逻辑像素内松手会吸附贴边，播「靠屏幕」入场后定格常驻；贴边期间不播待机一族的动作。
- **任务完成**：DSH 一次**顶层** agent 运行结束时，播一段完成动画 + 气泡「{对话名称}」完成 + 播放 `任务完成.mp3`，随后回到空闲。会话还没生成标题时气泡退化成「任务完成」。
- **任务出错**：该轮出过错时，中断完成动画、改摆 `晕.webp` + 气泡「{对话名称}」出错了，**不播音效**（只有一个「任务完成」音效，失败时放它是错的）。
- **任务终止**：你点了「终止对话」时，摆 `坐下.webp` + 气泡「{对话名称}」已终止，同样不播音效。既不庆祝也不当成错误——是你自己按的。
- **双击**：气泡显示当前 DeepSeek API 余额（`余额 ¥X.XX`），失败时显示原因。
- **右键**：弹出菜单。「设置」打开设置窗口（大小 / 气泡样式 / 气泡时长 / 台词 / 音效 / 重置位置 / 退出桌宠）。开发用的「测试面板」只在 `DSH_PET_DEBUG` 下露出。
- **单击**：无操作。
- **断连**：与 DSH 断开时空闲态换成 `寻找.webp` 并每 1.5 秒重连一次；DSH 重启能在 30 秒内回来就继续陪你，超过 30 秒则自行关窗（见下）。
- **穿透**：只有立绘本身吃鼠标事件，窗口其余部分（气泡留白区）的点击直接穿到背后的窗口（见下）。
- **尺寸**：立绘高度 = 屏幕短边（宽高中较小者）的 1/10 × 倍率，宽度按 3:4 等比；桌宠与气泡各有一个 50%~200% 的倍率，在设置里调；初启位于主屏右下角。

## 工作原理

1. 插件加载时启动一个本地 WebSocket 服务（`127.0.0.1`，动态空闲端口）。
2. 插件解析出当前平台的桌宠二进制并拉起进程，通过环境变量 `DSH_PET_WS_URL` 传入 WS 地址。
3. 桌宠连上后先发 `hello`（带自身版本）做协议对齐；随后接收 `task-complete` / `balance` / `balance-error` / `bye`，双击时回发 `balance` 请求。
4. 余额由插件（Node 端）用 `ctx.credentials` 里的 key 调 `GET {balanceBaseUrl}/user/balance`，key 不进入桌宠 webview。
5. DSH 退出/插件销毁时，插件注销自己的登记并广播 `bye`。

### 一只桌宠，多个 DSH profile

多开 profile 时每个插件都会拉起桌宠，而它们共用 `%LOCALAPPDATA%\com.dsh.deeppet`
下的 WebView2 数据目录、也就共用 localStorage，于是**落在像素级相同的位置上**
（实测两只都在 `1424,99`）——屏幕上看着只有一只，实际叠着两只，拖走上面那只
才会露出下面的。

做法是会合目录 `%LOCALAPPDATA%\com.dsh.deeppet\`：

- **单例**：桌宠启动时以「不共享」模式独占打开 `pet.lock` 并把句柄留住。第二个
  桌宠进程打不开这个文件，于是在显示窗口**之前**安静退出（窗口配置成初始隐藏，
  所以看不到闪烁）。用文件锁而不是 pid 文件，是因为前者在进程被强杀时由操作
  系统自动释放，不会留下需要判活的陈旧记录。
- **登记**：每个插件把自己的端口写进 `plugins/<pid>.json`，启动时顺手清掉 pid
  已死的陈旧登记。桌宠轮询这个目录，**主动连出去**连上每一个插件。
- **方向**为什么是「桌宠当客户端」：webview 里的 `WebSocket` 只能连不能听，
  让桌宠当服务端就得在 Rust 里再塞一个 WS 服务器加一层桥接；连出去则两侧现有
  代码几乎不动。
- **`bye` 的含义变了**：它表示「这个插件要走了」，不再表示「关闭桌宠」。关窗
  的判定改成——**登记目录空了 = 干净退出 = 立刻关窗**（实测 1.5 秒），
  **目录非空却连不上 = 崩溃 = 走 30 秒预算**。
- **插件不再 kill 桌宠进程**：先退出的那个 profile 会把别人还在用的桌宠杀掉。

`node test/rendezvous.mjs` 用真实二进制验证这三条：单例、一只桌宠连两个插件、
登记清空后立刻关窗。

### 怎么分辨任务是成了、砸了、还是被你叫停了

`AgentStatus` 只有 `idle` 和 `running` 两个值，所以 running→idle 这条边**在原理上
就分不出**这三者。判别器要从两个地方凑：

**`agent/error`**（Cordis 事件）——它的契约写明会报告失败「即使该错误在 turn 内
没有位置、没有持久记录」，也就是有些失败**压根不产生 `turn/end`**。

**`turn/end`**（session 日志事件，经 `ctx.on('session/event', (session, event) => …)`
观察）——`event.data.reason` 是个带判别标签的和类型：

| `reason.kind` | 含义 | 桌宠 |
|---|---|---|
| `completed` / `max-tokens` / `blocked` / `interrupted` | 正常收尾 | 完成 |
| `error` | turn 失败 | 出错 |
| `aborted` + `reason.kind: 'user' \| 'hook'` | 你或某个插件终止了它 | **已终止** |
| `aborted` + `reason.kind: 'parent' \| 'disposed'` | 上级撤销 / agent 正在销毁 | **完全不播报** |

**取消不发 `agent/error`**——这一条是在真实 DSH 上实测出来的：在网页端点「终止
对话」，桌宠会比耶庆祝。DSH 自己也知道这个坑，`consumed-work` 模块开头就写着
「一个还没进入第一步就停下的 turn，其 `turn/end` 和空操作 turn 长得一模一样」。

`parent` / `disposed` 必须是**完全不播报**，而不是「不算终止」——后者会落进
「完成」分支，变成关 DSH 时闪一下庆祝，比播报还糟。唯一的例外是同一轮里真出了
错：**出错优先于抑制**，DSH 退出途中的失败仍然要让用户看到。

优先级 **出错 > 已终止 > 完成**。三个标记都在 `running` 到来时清空，
`agent/disposed` 时连同 `prevStatus` 一起删除（否则这些容器会随会话数无界增长）。

把 `logEvents` 打开会把每条 `turn/end` 的 `reason`（含 `aborted` 的 cause）打进
DSH 日志，用来核对分类。

### 只庆祝顶层 agent

`ctx.agents` 上有 `list()`（所有存活 agent）和 `roots()`（顶层 agent——
"created without an owning agent context"）。**子 agent 同样会发 `agent/status`**，
所以一个任务内部派三个子 agent，原来会庆祝四次、放四遍音效。现在在 running→idle
时用 `roots()` 判定归属，只有顶层才播报。取不到 `agents` 服务时宁可多报也不漏报。

### 并发完成：合并而不是排队

排队会让桌宠播报几十秒前的状态，而桌宠的价值恰恰是「一眼看过去知道现在怎么样」。
所以同一轮爆发内的完成会合并：多个成功折叠成「「X」等 N 个任务完成」，**出错
优先占据气泡**（那才是你需要立刻看到的，另有几个成功会附在后面），音效每轮
最多响一次。

顺带修掉一个时序 bug：原来每次完成都排一个「回空闲」定时器，两次完成相隔 1 秒
时，旧的那个会在新气泡还挂着的时候触发，**立绘提前变回平常而文字还在**。现在
用自增的播报代次号，只有最新一次排的定时器生效。

### 我们依赖的 DSH 契约，谁来盯

插件监听 DSH 的事件、调用 `ctx.sessionTitle`，而这些定义**不在本仓库里**。
`test/plugin-smoke.mjs` 的 mock 是照着代码的期望造的，只能证明代码自洽——
DSH 那边改了形状，它照样全绿。

所以 `@deepseek-ai/dsh-agent`、`@deepseek-ai/dsh-session` 和
`@deepseek-ai/dsh-session-title` 既进了
`peerDependencies`（声明真实依赖），也进了本仓库的 `devDependencies`，
由 `test/contract.mjs` 读它们的 `.d.ts`，把我们实际依赖的那几条断言死：
`AgentStatus` 的取值、三个事件的载荷形状、`Agent.id` 的身份、
`sessionTitle.get` 可能返回 `undefined`、`turn/end` 的 `reason` 形状与四种取消
原因。契约一变，测试就红。

注意这些包的 npm `latest` 标签是**陈旧的**（指向 `0.0.1-rc.1`，而实际已到
`0.1.1-rc.2`），且 npm 的 prerelease 语义要求版本范围与目标版本
`[major,minor,patch]` 同元组才匹配——所以 peer 范围必须写成
`^0.1.0-rc.6 || ^0.1.1-rc.1` 这种逐条列举的形式，`^0.1.0-rc.6` 是匹配不到
`0.1.1-rc.2` 的。

### 桌宠不会变成孤儿

上面第 5 步只覆盖「DSH 正常退出」。DSH 崩溃或被强杀时插件的 cleanup 压根不会
执行，没人来杀桌宠——而一个置顶、无边框、又 `skipTaskbar` 的窗口一旦赖在桌面
上，用户连去哪找它都不知道。

所以"该死"的责任在桌宠自己，不依赖父进程做任何配合：断连后每
`RECONNECT_INTERVAL_MS`（1.5 秒）重连一次，累计断连超过 `RECONNECT_BUDGET_MS`
（30 秒）就 `appWindow.close()`。预算取 30 秒是为了让 DSH 正常重启（改配置、
HMR）期间桌宠能活下来——重连成功即清零。从未连上过的情况从进程启动时刻起算。

`node test/orphan.mjs` 用真实二进制验证这两条：短暂断连必须存活并重连，长断连
必须自我了断。

### 鼠标穿透

窗口尺寸是 `max(立绘宽, 气泡最大宽) × (立绘高 + 留白高)`——默认档下**宽度由
气泡决定，不由桌宠决定**，所以立绘只占窗口一小块。以 2560×1440 @150% 为例，
窗口 270×369 物理像素而立绘只有 108×144，**84% 的面积是全透明却照样吃点击的
死区**。（桌宠倍率调大后这个比例会下降，但死区不会消失，留白区始终在。）一个置顶
窗口带着这么大一块看不见的死区，桌宠飘到哪就挡住哪。

做法：默认整窗 `set_ignore_cursor_events(true)`，Rust 侧每 30ms 轮询全局光标
位置，落进命中区才切回可交互。命中区由前端用 `set_hit` 上报——平时是立绘的
布局盒，**拖动中和右键菜单打开时置 `force`**（穿透一开 webview 就收不到任何
鼠标事件，快速拖动会中断；菜单则需要窗口内任意一点都能点掉它）。

只加 CSS `pointer-events: none` 是不够的：那只让页面不响应，点击照样被这个窗口
吞掉，背后的窗口依然收不到。

拖动期间用的是 `force`（无条件可交互）而**不是「整窗矩形」**——这个区别很要命：
命中判定用的是光标**相对窗口**的坐标，而拖动时窗口是追着光标跑的，追不上时
光标就在窗口外面。若还按矩形判定，就会在拖动半途打开穿透，webview 当场失去
鼠标，拖动中断且再也收不到 `pointerup`，跑动动画卡死在那里。

### 桌宠为什么会「未响应」

用户报「经常未响应，双击才有反应」。`IsHungAppWindow` 实测为真——是字面意义的
主线程卡死，不是感觉慢。

成因全在命中测试的轮询里，而且是三层叠加：

**一、轮询每秒对主线程发起 100 次阻塞往返。** `should_ignore` 原来调的是
`win.scale_factor()` / `inner_position()` / `cursor_position()`，这三个在 Tauri
里都是 `window_getter!` 宏——**往主事件循环投一条消息，然后阻塞等回复**
（`tauri-runtime-wry/src/lib.rs`）。轮询 30ms 一跳，于是稳态就是每秒 100 次
往返，而主线程同时还在给 WebView2 合成带 alpha 的视频。

**二、这些往返是拿着锁做的。** `should_ignore` 从 `hit_state().lock()` 一路算到
底，中间就夹着上面那三次等待。而 `set_hit` 是个**同步**命令——Tauri 的同步命令
在 IPC 回调里就地执行，那个回调跑在主线程上。于是：

```
轮询线程：持有 hit_state 锁 → 等主线程回话
主线程　：在 set_hit 里 → 等 hit_state 锁
```

一个标准的环。

**三、翻转本身也要等主线程。** `set_ignore_cursor_events` 是往主事件循环投消息。
它不阻塞等回复，但轮询线程和它串在一条循环里——一旦这一步慢，检测也跟着停。

前两条对应的修法是**让轮询线程一次都不碰事件循环**：

- 光标、窗口原点、DPI 改成直接调 user32（`GetCursorPos` / `GetClientRect` +
  `ClientToScreen` / `GetDpiForWindow`）。
- 锁只在把 `force` 和 `rects` 拷出来的那几行里持有，出了那个块就放掉。即便现在
  已经不等主线程了，这个锁也不该跨任何可能阻塞的调用——这是结构约束，不是当下
  能不能跑通的问题。

第三条拆成两个线程：轮询只负责判断并把结果丢进通道（永不阻塞），另一个专职
线程去做那次可能慢的翻转，并且只认通道里最新的那个值。最坏情况变成「翻转晚
到」，而不是整条链路停摆。

> **试过绕开 Tauri 直接 `SetWindowLongPtrW` 改 `WS_EX_TRANSPARENT`，更糟，已撤回。**
> 那是别的线程拥有的窗口，改扩展样式同样要和属主线程同步——实测前 3 次翻转
> 正常，之后轮询线程就卡死在那一句里，窗口永远停在穿透态（12 轮超时 9 轮）。
> 「直接调 Win32 就没有跨线程代价」这个直觉，对查询成立，对改窗口样式不成立。

`node test/responsive.mjs` 守着这个：它必须**同时**制造两个条件才测得出来——
主线程有负载（播 alpha 视频）+ 反复触发开关翻转，少一个都测不到。断言三条：
压测期间 `IsHungAppWindow` 一次都不为真、翻转延迟的中位数在一个轮询周期量级、
没有任何一轮翻不过来。修复后实测中位 30ms、最差 47ms、零超时。

> 这个测试注入鼠标位置，所以**它必须能分辨「桌宠没反应」和「人把鼠标挪走了」**。
> 一开始没分辨，于是一堆随机超时——我拿着 Rust 侧的判定日志才发现光标压根不在
> 立绘上，桌宠判「在外面」完全正确。现在每次采样都回读一次光标位置，被人手
> 打断的轮次直接丢弃并单独计数；有效样本不足时测试会明说，而不是拿三两个样本
> 下结论。
>
> 那份判定日志（`get_hit_debug`，把光标、窗口原点、命中矩形和结论一起摊开）
> 留在代码里了——正是它把「判错了」和「判对了但没生效」区分开的。

> 顺带一提：本机已经有一只桌宠在跑时，测试拉起的那只会抢不到单例锁而**立刻
> 自杀**，从前的表现是挂到超时再报一句含糊的「桌宠未连上」。现在
> `test/lib/wait-pet.mjs` 把这种情况检测出来直接 SKIP 并说明原因——判据是桌宠
> **进程**在不在，不是会合目录里有没有插件登记（后者说明的是 DSH 在跑，那时
> 桌宠可能已经自我了断了，是两回事）。

### 快速拖动为什么会把桌宠卡在跑动状态

拖得快时窗口跟不上光标，光标跑出窗口，于是 `pointerup` 落到了别的窗口上——
`img` 的 `pointerup` / `lostpointercapture` 一个都不触发，`window.blur` 也不会
（这个窗口 `skipTaskbar` + 无边框，压根没拿到过焦点），`dragging` 就永远是
`true`。慢慢拖时光标始终在立绘上，所以没事。

四处一起治：

- **抢指针捕获提前到 `await` 之前**。原来它排在 `await appWindow.outerPosition()`
  之后，而那是一次到 Rust 的 IPC 往返——快速拖动时光标在这几毫秒里就能跑出
  立绘范围，等 `await` 回来再抢已经晚了。
- **位置更新合帧**。`pointermove` 在高回报率鼠标上能到几百 Hz，而每次
  `setPosition` 都是一次 IPC 往返；不合帧就会堆出一串过期指令，窗口越追越落后
  ——这正是光标跑出窗口的根源。现在每个动画帧只发最新的一次。
- **`pointerup` / `pointercancel` 同时挂到 `window` 上**，捕获万一没抢到，落在
  窗口内任意位置的抬起仍能收尾。
- **`pointermove` 里看到 `e.buttons === 0` 就收尾**——最后一道兜底：即使那次
  `pointerup` 彻底丢了，光标一回到立绘上就能把卡住的状态收回来。

另外抓取偏移在算出来之前不允许移动窗口（`grabReady`），否则第一帧会拿上一次
拖动残留的偏移把窗口甩出去。

#### 点击不是拖动

`pointerdown` 里有两件事从前是一起做的，其实必须分开：

- `dragging`（命中区 `force`）**必须立即置位**——晚一步光标就跑出窗口了，
  就是上面那个 bug。
- `st.dragging`（跑步动画）**要等真的移动超过阈值**。混在一起的后果是任何一次
  点击都会闪一下跑步动画，双击时闪两下。位移阈值当时只用来决定「移不移窗口」，
  没有用来决定「进不进跑步态」。

阈值统一成 8 逻辑像素（原来是 4，对点击时的手抖太敏感），移动窗口、进跑步态、
松手后吸附三件事共用它。「一拖就离开贴边态」也挪到越过阈值那一刻——点一下趴在
屏幕边的桌宠不该把它弄下来。

`node test/dblclick.mjs` 注入真实鼠标事件验证：双击后不进跑步态、真拖动时进、
松手后退出。**反向那两条不能省**——只测「双击不跑」的话，一个永远不跑的实现也
能通过。

#### 那个左上角 0,0 的 22×22 窗口不用管

枚举桌宠进程的窗口会看到第二个「可见」的顶层窗口：类名 **Tao Thread Event
Target**，位于屏幕 `0,0`，22×22 物理像素。它是 Tao（Tauri 底层的窗口库）用来
收线程级消息的内部窗口，不是 UI。已实测确认无害：

- **不画任何东西**：屏幕左上角 48×48 区域在桌宠运行前 / 运行中 / 退出后三次
  抓取的哈希完全一致（前后两次静态抓取相同，说明该区域本身稳定，对比才成立）。
  它是 LAYERED 窗口但从未被 `SetLayeredWindowAttributes` / `UpdateLayeredWindow`
  定义过内容，而未定义内容的分层窗口不显示。
- **不吃点击**：它带 `WS_EX_TRANSPARENT`；在它矩形内取三个点做
  `WindowFromPoint`，返回的都是别的进程的窗口。
- **不进任务栏和 Alt+Tab**：带 `WS_EX_TOOLWINDOW`。

会引起注意只是因为 `IsWindowVisible` 对它返回 true——那个 API 只反映
`WS_VISIBLE` 样式位，**和「屏幕上有没有画出东西」无关**。仓库里按窗口取样的
脚本都取面积最大的那个，所以不会误选到它。

`node test/clickthrough.mjs` 用 Win32 `WindowFromPoint` 在操作系统层面验证，并
回读 `WS_EX_TRANSPARENT` 位以区分「开关没翻」和「探测点不对」。注意分层窗口会按
**逐像素 alpha** 命中测试，所以立绘包围盒内的全透明像素本来就会穿透——探测点要
打在立绘中心，不能打在边缘。

### 贴边：贴的是立绘，不是窗口

窗口宽度取的是 `max(立绘宽, 气泡宽)`，默认档下气泡留白远宽于立绘——1080p 下
窗口 180 逻辑像素、立绘只有 81，立绘居中放置，**两侧各空出约 50px 全透明边距**。
吸附时若按窗口边对齐，贴完立绘离屏幕边还差这 50px，看起来就是「没真正靠边」。
（把桌宠倍率调大到立绘比气泡还宽时这段边距会缩到 0，下面这套算术照样成立。）

所以判定和对齐都针对立绘盒：

```
inset = (窗口宽 - 立绘宽) / 2
贴左：窗口 x = 屏幕左 - inset
贴右：窗口 x = 屏幕右 - 窗口宽 + inset
```

代价是贴边后窗口有 `inset` 那么宽悬在屏幕外，这是有意为之。连带的问题是**气泡
的可见带也窄了这么多**，直接居中会被屏幕边裁掉一半。策略是「能居中就居中」
（尖角正对立绘，最自然），放不下才最小幅度内移，并把尖角按相反方向挪回立绘
中心——气泡整体挪了多少，`--tail-shift` 就挪回多少，再夹一层保证尖角不跑出
圆角外。这套算术抽在 `pet/src/bubble-layout.js`（写成 `.js` 是为了能被 node
直接 import），由 `test/bubble-layout.mjs` 穷举验证。

`node test/edge.mjs` 在真实二进制上端到端验证，它刻意**不复用**桌宠算贴边时用
的那个 `inset`——桌宠报出 `img.getBoundingClientRect()`（DOM 量的真实布局盒），
探针独立从 Win32 拿窗口矩形和显示器矩形，两边对上才算数；否则就是自己验自己。
再加一条：立绘**盒**贴住了不等于**画面**贴住了，靠边姿势如果在帧里留了内边距，
看上去仍然是浮着的，所以探针还会扫出真实落笔的列。本机实测两侧都是 0px。

> 如果以后换的靠边素材在帧边留了空白，不必改代码——在 `assets/动作清单.json`
> 里给那个动作加一个偏移字段即可，这条测试会把问题指出来。

### 测试面板

**这个入口只在 `DSH_PET_DEBUG` 下露出**——它是开发用的，社区版本的右键菜单
不该有它。功能本身一直在（Rust 的 `open_test` 命令、调试通道都在），
`test/panel.mjs` 走的也是调试通道而不是那个按钮。

隐藏用的是 `hidden` 属性 **加一条显式的 `.menu-item[hidden] { display: none }`**：
类选择器的优先级高于浏览器默认的 `[hidden] { display: none }`，光加属性是藏不住
的，按钮会照常显示出去。菜单的定位也改成现量 `offsetWidth/offsetHeight` 而不是
写死——菜单项数会变，写死的高度会让它在屏幕下沿被摆到错的位置。

右键菜单里的第二项，独立窗口。三段：

- **动作预览**：按池分组列出 `动作/index.json` 里的每个动作，点一下就在桌面上
  那只**真桌宠**身上播。面板里刻意不内嵌预览——内嵌至多能证明视频文件可解码，
  证明不了透明合成、尺寸、镜像和命中区，而那几样恰恰是最容易出错的。
- **事件触发**：任务开始/结束、完成/出错/已终止、进出长闲、强制贴左右、复位。
  不需要连着 DSH 也能用。
- **实时事件日志**：每条进度事件的去向（已显示 / 被 todo 遮蔽 / 被新事件覆盖 /
  被播报占用 / 任务已结束）。**只记工具名和脱敏后的气泡文本，不记参数原文**
  ——这个窗口会出现在你的录屏里。面板关着时桌宠一次 IPC 都不发。

`open_test` 和 `open_settings` 一样**必须是 `async`**，原因见上「设置面板」。
`node test/panel.mjs` 会真的把它打开并抓图，因为纯白窗口正是那个坑的样子。
抓图用 `PrintWindow` 而不是 `CopyFromScreen`：后台进程在 Windows 上抢不到前台，
截屏会把当时压在上面的**任何**窗口一起抓进来（这事已经发生过一次）。

### 素材流水线

素材有两条硬约束：`frontendDist` 会把整个 dist **嵌进 exe**，所以进 `pet/public`
的每个字节都会变成二进制字节、再变成每个用户要下的 npm 包字节；而立绘实际只
显示约 **108×144 物理像素**。改造前 `assets/` 和 `pet/public/` 是两份**字节级
相同**的手工拷贝（各 18.7 MB，都在 git 里），其中 9.6 MB 是 README 自己标注为
「参考用、非运行时素材」的 1536×1024 总览大图——它们一直在随包分发。

现在 `assets/` 是唯一真源，`pet/public/` 由 `scripts/build-assets.mjs` 按一份
**显式清单**装配，并已 gitignore。清单里没有那几张总览图，所以它们从结构上
不可能再进二进制；双份不同步这类 bug 也一并消失，因为第二份不再由人维护。

同时立绘转成 WebP（q95）——PNG 对平涂动漫图效率很低：

| | 改造前 | 改造后 |
|---|---|---|
| 运行时素材 | 18.7 MB | **3.7 MB** |
| exe | 27.7 MB | **11 MB** |
| npm 包 | 21.7 MB | **6 MB** |

q95 是看过 3 倍放大对比后选的：q95/q90/q80 在实际显示尺寸下都看不出差别，
q95 相对 q90 只多约 350 KB，留作将来「桌宠尺寸」设置的余量。

装配的同时会做**取景归一化**（见上），取景基准由 `scripts/lib/framing.mjs`
统一提供——动作流水线和立绘流水线共用同一处基准，不会各算各的。

`node scripts/build-assets.mjs` 已挂在 `pnpm build` / `pnpm dev` 前面，正常开发
不用手动跑。

### 完成动画

母版是 576×736、30fps、5.17 秒的 **qtrle（`argb`）** `.mov`，95 MB，**不进 git**，
留在仓库外。`scripts/build-animation.mjs` 从它转出 `done.webm`（288×384 @15fps
VP9-alpha，约 0.5 MB）——转出的 webm 进 git，于是 CI 和新克隆都不需要母版。
它和其余动作走完全相同的流水线，没有专用分支。

几个不显然的决定：

- **`.mov` 不能当运行时素材**。WebView2 不解码 qtrle，容器也不支持。同一份
  母版另外导出的 h264 和 hevc 版本 `pix_fmt` 都是 `yuv420p`——**没有 alpha**
  （H.264/HEVC 本身不携带透明度；HEVC-with-alpha 是苹果生态专有的）。它们的
  背景被压平成纯黑，而角色最暗处（鞋子）亮度只有 8/255，和背景差 8 级——
  在有损 4:2:0 编码里没有任何安全的抠黑阈值。只有 qtrle 那版能用。
- **一度用帧序列，后来改回 WebM**。当初的理由是「Windows 上 Chromium 会把视频
  提升到 DirectComposition 覆盖平面、绕过页面合成，在透明置顶窗口里变成黑块」——
  但那是条**未经验证**的风险。后来动作从 1 段涨到 9 段，帧序列的代价从 1.1 MB
  涨到约 19 MB，才补做了实验：透明置顶窗口里 VP9-alpha 合成正确。风险不成立，
  于是全部改用 WebM（详见「动作库」）。
- **为什么压成 3:4**。母版 576×736（0.7826）比立绘 384×512（0.75）宽 4.3%，
  压成 3:4 让动画能复用立绘那一套尺寸计算，不需要新的布局代码。至于角色在帧内
  画得多大——那是另一回事，由取景归一化处理（见上），两者不要混为一谈。
- **`bubbleMs` 说了算，但不砍动画**。预算短于原生时长（5.2 秒）时按比例加速，
  让动画完整播完；长于时按原速播完并**定格在最后一帧**（双手合十，本来就是
  个完整姿势）。硬切会把一次性动画停在中间姿势再跳回平常，那看起来就是坏了。
- **合并时不重播**。后续完成并入同一轮爆发只更新气泡文字；播到一半重头来会
  明显卡顿。只有「出错抢占成功」才中断动画。

### 尺寸倍率

桌宠和气泡各有一个倍率，分开调——它们是两种东西：一个是画面主体，一个是拿来
读字的。绑在一起的话，把桌宠调小会连带把字缩到看不清。

**缩放锚点是脚底 + 水平中心。** 窗口默认钉住左上角长大，那会让桌宠往下沉——
本来站在屏幕底部的话直接沉出屏幕。锚在脚底才读作「她长大了」而不是「她挪位
了」。Rust 只管尺寸和这个锚点，贴边重新对齐和越界回收留给前端做：贴的是哪一边
只有前端知道，而窗口两侧本来就有一段是**故意悬在屏幕外**的，按窗口边收会把贴边
状态一起收掉。

**桌宠倍率的上限跟屏幕走。** 动作视频的原生高度是 384px，桌宠比它还大就是在
放大视频、边缘发虚。所以上限取 `min(200%, 384 ÷ (屏幕短边÷10))`：

| 屏幕 | 100% 时立绘高 | 实际上限 |
|---|---|---|
| 1080p | 108 | 200% |
| 1440p | 144 | 200% |
| 4K | 216 | **178%** |

只有 4K 以上会真的被压低，这时设置面板里会写明原因——否则那个滑块看起来就是
坏的。

**气泡是整体缩放**：字号、内边距、圆角、尖角、最大宽度、以及窗口上方的留白区
一起乘。为此 `bubble.css` 里字号必须是独立变量而不是 `font` 简写的一部分
（五种样式各自覆盖字号，简写没法只乘其中一段），其余尺寸一律用 `em` 表达，于是
一个 `--bubble-scale` 就带动全部。留白区不跟着长的话，调大气泡后两行的气泡会
顶出窗口上沿被裁掉。

拖滑块时走 `preview_size` 只重算窗口、不写盘，松手才 `set_settings` 落盘——
一次拖动几十次 `input`，每次写一遍 JSON 又蠢又慢。

### 气泡为什么会断成两行

用户报「🔧 正在执行 npm 命令」折成两行。量下来这一串是 **162 逻辑像素**，而
当时的上限是 168——**只剩 6px 余量**，换个 DPI 字体排宽一点就翻车。

而那个 168 是我自己造的：贴边留的 6px 边距被**两侧都扣了一遍**，180 直接变
168。那个边距的用途是「贴边时气泡别顶到屏幕边」，可另一侧压根没有屏幕边在旁边
——那里的界限是窗口边，隔着一段全透明区域，气泡正好贴住也看不出来。改成只扣被
屏幕边裁掉的那一侧，余量从 6px 回到 18px。

另外两层是给更长的串兜底：

- 程序名和「命令」之间用**不断行空格**（U+00A0）绑死，断点只能落在「正在执行」
  之后，不会出现第二行只剩「命令」两个字的情形。测试里单独钉了一条断言查那个
  码点——光比字符串的话，改回普通空格时期望值也会跟着改，那条断言就白设了。
- `text-wrap: balance` 让两行长度拉平。不支持的内核忽略它，退化成普通折行。

### 台词

桌宠会自己说话：完成、出错、已终止、任务开始、任务跑得久、连续失败，六个池
共 72 句，随机抽。台词是**数据不是代码**——加一句只改 `assets/台词.json`：

```json
{ "t": "嘿嘿，又完成一个！", "face": "哼哼" }
```

`face` 指向 `立绘/表情` 里的一张图。那 23 张一直全都打进 exe，但代码只引用了
4 张（平常/寻找/晕/坐下）——现在按 `face` 用起来，零体积成本。成功仍然播
`done.webm`（那是它的高光，换静图是降级），变化的是台词。

**台词当主角，原来那句信息降为副行**：第一行「搞定！」，第二行小一号的
`「重构气泡布局」完成`。并发时靠副行分辨是哪个任务完了。标题为空时副行会退化
成「任务完成」这种废话，那时直接省掉。副行用 `textContent` 逐段写，**不拼
`innerHTML`**——标题是模型生成的文本，拼 HTML 等于把它当标记解释。

**频率是分类压的**，不是一刀切：

| 类别 | 触发 | 约束 |
|---|---|---|
| 完成 / 出错 / 终止 | 已有信号 | 每次都说（那本来就是你要的反馈） |
| 开场 | `working` 转 true | 3 分钟冷却——连跑 20 个小任务就是 20 句「交给我吧」 |
| 跑得久 | ≥90 秒 **或** ≥12 次工具调用且已干满 15 秒 | 每任务最多一次 |
| 连续失败 | 第 2 次起连续 error | 每次说，成功即清零 |

「≥12 次工具调用」还要求真干了一会儿：十几个飞快的调用只说明活儿碎，不说明
难，那时说「这个有点难」是错的。

**开始那一刻判断不了难易**——插件手里只有 `agent/status: running`，没有提示词、
没有工具调用、没有 todo。所以「这个看起来有点难」只能中途说，开场白是通用的。

中途台词会**抢拍**进度气泡：一个任务里最多说一次，抢一下不乱；而进度本来就是
间歇的，少一条无所谓。被抢掉的那条走既有的「被播报占用」记进测试日志。

**工作中的台词只占气泡，不动身体。** 第一版顺手把台词的 `face` 也 `showStill`
了出去，结果是任务开始后好几秒不打字：`setWorking` 在同一个 tick 里先
`render()` 发起 `playAction("typing-intro")`，紧接着 `speak()` 里的
`showStill` 又 `++playGen`，把刚发起的那次视频交接**作废**（`playAction`
醒来发现代数不符就退出）。而开场白有 3 分钟冷却，只有隔了一阵的第一个任务才
会这样——表现为间歇性「不打字」，最难查的那种。所以只有 `error` / `canceled`
两池真的会换表情。

连续失败的计数在插件侧，内存里存，任一成功清零。**「已终止」既不清零也不累加**
——那是用户按的，不是桌宠失败了。

设置里有开关，关掉就回到纯信息播报。想改称呼或口味：把 `台词.json` 复制到
`%LOCALAPPDATA%` 下的 `com.dsh.deeppet/lines.json`，存在就**整体替换**内置那份
（不是逐池合并——合并的话「只想改完成那一池」和「想删掉某几句」会给出完全
不同的直觉，说不清楚）。默认池里只有约三分之一带「主人」这个称呼，每句都带会腻。

两层测试：`test/lines.mjs` 逐条核对每个 `face` 是否真实存在（写错一个字就是
一张裂图，而那种错**只有肉眼看得见**，桌宠不会报错，它只是显示不出来）；
`test/speech.mjs` 在真桌宠上验触发——出错用 error 池、连续失败换 streak 池、
连抽 6 次没有相邻重复、关掉开关后回到信息播报。

### 气泡样式

5 种手工精调的样式：**经典**（白底圆角）、**暗色**（深色半透明）、**玻璃**
（半透明 + 斜向高光）、**便签**（暖色纸感、方角、微倾）、**像素**（硬边、粗描边、
阶梯状尖角）。用固定样式类而非参数化主题——玻璃要高光和渐变、像素要硬边和
阶梯尖角、便签要纸感和微倾，这些差异在同一组参数里表达不出来。

外观规则单独放在 `src/bubble.css`，定位规则留在 `styles.css` 的 `#bubble` 上。
拆开是为了让**设置窗口用同一份 CSS 渲染样式预览**——预览和真实气泡必须是同一套
规则，否则「所见」和「所得」会慢慢分家。

两个容易踩的点：

- **真正的毛玻璃做不到。** `backdrop-filter` 只能模糊页面内它下面的东西，而桌宠
  窗口是透明的、气泡下面什么都没有——桌面像素属于操作系统合成层，渲染进程拿不到。
  OS 级的 acrylic/mica 又只能作用于**整个窗口**，会把立绘周围那一大片留白也变成
  磨砂玻璃板。所以「玻璃」是半透明底色 + 高光 + 亮描边仿出来的。
- **小尖角必须跟着底色走。** 它是 `::after` 画的，写死白色的话换成暗色样式就会
  露出一个白尖角。现在跟 `--bg` / `--border` 走；像素样式则用 `clip-path` 切出
  阶梯状尖角，因为旋转 45° 的菱形在硬边风格里会露出斜边。

### 设置面板

独立窗口，不是桌宠窗口内的浮层——桌宠窗口的每一条属性（透明、置顶、无边框、
大部分穿透、尺寸绑定立绘）对设置面板都是负担，硬塞进去等于让它继承一整套不需要
的约束再逐条对抗；而且窗口只有 180×246 逻辑像素，面板宽度会被立绘尺寸绑架。

设置存 `%LOCALAPPDATA%\com.dsh.deeppet\settings.json`，由 Rust 读写。**归属是
关键**：一只桌宠服务 N 个插件，设置存进某个 profile 的 cordis 配置就说不清谁
说了算。所以 `bubbleMs` 也从插件配置搬到了这里；`label` 留在插件侧，因为它本来
就是每 profile 一份。设置文件读坏了一律回默认值——它不该让桌宠起不来。

设置窗口和桌宠窗口是两个 webview，靠 Rust 转发的 `settings-changed` 事件同步，
改了立刻生效。

**`open_settings` 必须是 `async`。** 同步命令跑在工作线程上，而 Windows 下
WebView2 的初始化要走主线程事件循环——同步创建的结果是窗口框架建出来了、webview
永远初始化不了，表现为一个纯白空窗口，而且后续 `win.url()` 会直接把调用方卡死
（既不 resolve 也不 reject）。这是 Tauri 在 Windows 上的已知陷阱，改成 `async`
即可。

### 动作库

动作由 `assets/动作清单.json` 驱动，构建时转成 **WebM（VP9 + alpha）**。加一个动作 =
把 `.mov` 母版放进素材目录 + 在清单里加一行，**不用改代码**：

```json
{ "id": "typing-intro", "file": "开始打字.mov", "pool": "working",
  "role": "intro", "next": "typing-loop" }
```

`role` / `next` / `hold` 表达了文件名约定表达不了的东西——入场接循环、循环、
播完导出末帧静图供常驻。母版每个 70~140 MB **不进 git**，转出的 webm 进 git，
所以 CI 和新克隆都不需要素材。

**为什么是 WebM 而不是帧序列。** 新增的 8 段动作在 15fps 下共 978 帧，按 WebP
帧序列约 **24 MB**——会把二进制顶回一切优化之前。同分辨率 WebM 约 **5 MB**，
小 4.7 倍。

早先的版本用帧序列，理由是「Windows 上 Chromium 会把视频提升到
DirectComposition 覆盖层、在透明窗口里变成不透明黑块」——但那是个**未验证**的
风险。赌注从 1.2 MB 涨到 13 MB 之后补做了实验：透明置顶窗口里播 VP9-alpha，
背后的内容一直透到角色轮廓边缘，没有黑框。风险不成立，于是改用 WebM。

验证途中差点被一个假信号误导：`ffprobe` 对转出的文件报 `pix_fmt=yuv420p`，
看着像 alpha 丢了——但**已确认能透明渲染的文件也报 `yuv420p`**。WebM 的 alpha
存在容器旁路，ffprobe 和 ffmpeg 的 rgba 解码都测不出来。真判据是让 Chromium
解码后读画布像素：角落 α=0、身体 α=255、每帧 44～47% 完全透明。

### 播放通道：新的准备好了再撤旧的

静图走 `<img>`，动作走**两个轮换的 `<video>`**。原来只有一个 video、且交接规则
只守了一半，于是三处都在闪：

| 切换 | 原来的做法 | 后果 |
|---|---|---|
| 静图 → 视频 | 等 `playing` 再隐藏静图 | 正确 |
| 视频 → 静图 | 设完 `img.src` 就立刻藏掉视频 | 图还没解码完，两边都没内容 |
| 视频 → 视频 | 在同一个 `<video>` 上换 `src` | 换 src 会**立刻清空当前帧** |

第三条命中每一次 `typing-intro → typing-loop`、每一次长闲换动作、每一次
`edge-lean → 定格`——凡是动作接动作的地方都闪。

现在两个方向都守同一条规则：

- **视频 → 视频**：新动作装进当前没在显示的那个元素，旧的**定格在最后一帧**
  继续显示，等新的真的呈现出第一帧再硬切。等待用 `requestVideoFrameCallback`
  （它的语义正是「已呈现一帧」，比只表示「播放已开始」的 `playing` 准），
  并挂 `playing` 和超时兜底，免得解码失败时画面永远卡在旧层。
- **→ 静图**：先在离屏 `Image` 上 `decode()`，解码完才赋给 `#pet-img`、点亮，
  **最后**才撤视频层。

两个 video 的隐藏一律用 `opacity` 而不是 `display:none`：`display:none` 的
video 在 Chromium 里可能不再产出帧，那样「等第一帧」就永远等不到。`#pet-img`
则始终只有一个——拖动、双击、右键和命中区都挂在它身上。

异步等待期间可能又来了新的播放请求，所以每次交接带一个代数号，醒来发现代数
变了就自觉作废，不然会把过时的画面盖回屏幕。

### 取景归一化：三套画对齐成一套

从静图切到动作时角色会「胀」一下。**两边画布都是 3:4，问题不在比例**，在角色
在帧里画得多大——量下来素材本身就有三套取景：

| | 角色高占画面 | 脚底留白 | 呆毛顶 |
|---|---|---|---|
| 立绘 23 张 | 93.8% | 4.7% | y=8 |
| 开始打字（母版） | 93.5% | 4.9% | y=7 |
| 其余 7 段动作（母版） | **97.4%** | 2.6% | **y=0** |

也就是说母版自己就分两批，相差约 4%。**先按 idle 组校准过一次，结果是把
「平常 → 待机动画」修好、把「平常 → 开始打字」弄坏**——那两条路原本恰好吻合。
只对齐一边等于把问题挪个地方。

以立绘为准归一化全部素材之后，每个变换都是**缩小或不变**，因此不可能裁掉像素；
反过来以动作为准的话，立绘和开始打字都要放大，实测会裁掉 20 张的发梢和手指。

规则：

- **缩放**：动作按各自首帧算一个系数，**整段共用**——逐帧对齐会把动作自己的
  位移抹平，那不是归一化取景，是把动画做成了原地不动。立绘这边系数正好是 1
  （基准就是「平常」）。
- **垂直**：包围盒底对到同一条基线。表情逐张对；**跑步 8 帧整组对**，锚点取
  组内最低点（脚踩地的那一帧）——8 帧的包围盒底在 468~498 之间起伏 30px，那是
  跑动的颠簸，逐帧对齐会把它压平。
- **水平**：**不动**。包围盒中心会被抬起的手臂带偏（表情间散布 25px、跑步 8 帧
  散布 20px），按它对齐等于为了迁就手臂去挪身体。
- **不对齐高度**，只对基线：坐下比站着矮是对的，硬拉到等高就成了「坐着却和
  站着一样高」。

两个脚本共用 `scripts/lib/framing.mjs`，基准只有一处。构建时会把每张的溢出量
打印出来——顶出画布是「这张该重画」的信号，而不是需要静默容忍的事。

> 量 WebM 的 alpha 必须显式 `-vcodec libvpx-vp9`。默认的 vp9 解码器会丢掉
> WebM 的 alpha 边通道，量出来是「整幅不透明」——第一次跑就撞上了，所有动作
> 齐刷刷报 100%。和 `ffprobe` 报 `yuv420p` 是同一个坑的两个出口。

### 状态仲裁

优先级（高者胜）：**拖动 > 播报 > 工作中 > 长闲 > 随机待机 > 平常**。

「贴边」**不在这个序列里**，它是正交的模式：贴边期间身体固定为趴屏幕的静图、
压掉待机一族，而工作/播报只出气泡不换身体。位置归你，状态归它——贴边时 DSH
开始任务不会把窗口挪回去。

只有呈现**类别**变了才重新进场，否则合并进来的后续事件会把正在播的动作打断
重来。「新任务打断上一轮播报」是**时序失效**（播报的内容不再为真），和优先级
比较是两回事，代码里分开写。

有三处用 `display:none` 隐藏 `<img>` 会连带出问题，所以改用 `opacity`：
`display:none` 的元素 `offsetWidth` 为 0，**命中区会归零**让整只桌宠变穿透、
拖不动；而拖动/双击/右键的监听器都挂在 `img` 上，隐藏后它**收不到任何鼠标
事件**。`opacity:0` 只熄灭绘制，布局盒和命中测试都还在。

### 任务进度气泡

内容全部来自真实数据，不编轮播文案：`todo/write` 里 `in_progress` 那条的
`content`（契约写明是「a short imperative line shown in the UI」）优先，
`tool/call` 的工具名 + 参数兜底。一条 todo 之后 2 秒内压住工具级进度，
免得刚出现就被「正在修改 x.ts」盖掉。

**限流全部在桌宠侧，插件无条件下发每一条。** 遮蔽判定原本在插件里，被压掉的
事件就此消失——于是「有过这个事件、但被丢了」在任何地方都看不到。这条路上曾经
埋着一个真实故障：插件侧 6 秒的 todo 遮蔽叠上桌宠侧 2.5s+5s 的冷却，一个 turn
里最靠前的那几个工具调用（`think`、`pwsh` 之类）整个落进盲区，一条都看不到，
而排查时连「它们来过」都无从确认。现在插件只负责脱敏和分类（并带上未截断的
工具名），仲裁集中在 `onProgress`，每一次判定都进测试面板的日志。

**脱敏不是可选项**：这个气泡是置顶的，会出现在截屏、录屏和屏幕共享里。

- 文件路径**只显示文件名**——完整路径既塞不进 180px 的气泡，也不该进你的截屏。
- shell 命令**只显示程序名**，绝不显示完整命令行——那正是密钥出没的地方
  （`curl -H "Authorization: Bearer sk-..."`）。带引号的程序路径按引号解析；
  不带引号又含空格的路径本身歧义，**精度可以退化，安全不能**。
- todo 内容截断到 24 字。

`node test/progress.mjs` 用真实二进制断言这几次判定：`think` 能显示、`pwsh`
能显示、紧跟 todo 的那条被让位、且**每条进度都有明确去向**。

`node test/redact.mjs` 把脱敏断言死。写这个测试时踩了个值得记的坑：测试输入里的
`\` 在多层转义中被折叠成 `\`，随后 JS 把 `\P` `\s` 当转义符吃掉，
**反斜杠凭空消失**——测的就不是实现而是转义了。实现和测试现在都用
`String.fromCharCode(92)` 构造反斜杠。

### 桌宠二进制怎么来的

二进制**不**在运行时下载，而是随插件一起由 npm 解析：插件把各平台二进制声明为
`optionalDependencies`（如 `dsh-deep-pet-win32-x64`），包内的 `os` / `cpu` 字段让
npm/pnpm 只安装匹配当前平台的那一个，版本对插件是**精确 pin**。

这样一来插件与二进制永远同版本，完整性由 npm 自己的 integrity hash 保证，
既不存在缓存陈旧，也不需要额外的校验逻辑。运行时若因为某种原因版本仍然对不上
（例如手工指定了 `petBinary`），`hello` 握手会在 DSH 日志里给出警告。

## 安装

```bash
dsh plugin --profile web add dsh-deep-pet
```

安装时**不要**跳过 optional 依赖（`--no-optional` / `--omit=optional` 会让桌宠
二进制装不上，插件启动时会在日志里明说）。装好后重启 DSH（`dsh --profile web`），
加载插件时会自动拉起桌宠窗口。

当前只提供 **Windows x64** 二进制。其他平台需自行编译，再用 `petBinary` 指过去。

## 本地开发

需要：Rust（MSVC 工具链）、pnpm、Node ≥ 18、Windows 需已装 WebView2。

```powershell
cd pet
pnpm install
pnpm tauri icon ..\assets\立绘\表情\平常.png   # 生成应用图标（一次性）
pnpm tauri build --no-bundle                   # 编译 release 二进制
cd ..
node scripts/stage-binary.mjs                  # 把二进制放进当前平台的发布包
```

跑测试：

```bash
npm test                   # 版本一致性 + DSH 契约 + 素材取景 + 插件冒烟 + 握手回归
npm run test:integration   # 真的拉起 exe，验证连上并完成握手（约 7 秒）
npm run test:clickthrough  # 鼠标穿透 + 拖动 force 路径（会短暂移动鼠标指针，测完复位）
npm run test:rendezvous    # 单例 / 一只桌宠连多个插件 / 干净退出（约 40 秒）
npm run test:orphan        # 断连兜底：短暂断连存活 / 长断连自尽（约 50 秒）
npm run test:live          # 下面九项一次跑完（约 3 分钟）
npm run test:edge          # 贴边：立绘（不是窗口）真的贴住屏幕边
npm run test:dblclick      # 双击不误触跑步、拖动仍正常（会短暂移动鼠标并注入点击）
npm run test:progress      # 进度限流的每一次判定
npm run test:panel         # 测试面板真的打开并渲染出内容
npm run test:size          # 尺寸倍率（脚底不动）与气泡不折行
npm run test:speech        # 台词的触发、换池、不重复、开关
npm run test:responsive    # 压测下主线程不卡死、穿透开关及时翻转
npm run test:framing-live  # 屏幕上静图与各动作的脚底落在同一条线上
npm run test:flicker       # 切换动作时没有空帧（就是肉眼看到的那一闪）
```

`npm test` 里有两个纯算术/纯量测、不需要跑起桌宠的：

- `test/bubble-layout.mjs` 穷举各种窗口/立绘/气泡宽度，钉死两条不变量：气泡
  永远落在可见带内、尖角永远不跑出气泡。
- `test/menu.mjs` 静态查三个条件：那一项默认带 `hidden`、CSS 里有显式的
  `.menu-item[hidden] { display: none }`、只有 `debugMode` 会放出它。三条缺一
  就会静悄悄把开发按钮发给用户。
- `test/framing.mjs` 量**产物素材**的几何，钉死取景不变量。它同时守着两个
  真实踩过的坑：动作首帧若报「角色占满整幅」就直接判失败（那说明 WebM 的
  alpha 边通道又被丢了，整套校准会建在假数上）；接续段的缩放必须和上一段
  一致（`typing-loop` 曾被单独放大 9%）。

`test/flicker.mjs` 值得单说：闪动只持续一两帧，而一次 PrintWindow 就要 300ms，
截图**抓不到**。所以桌宠在调试模式下按 rAF 自己盯「静图熄了而视频没有画面」
这个不变量并累计空帧数，测试驱动一串最容易出问题的切换再读计数。这个测试做过
反向对照：把修复退回去（先撤视频再等解码）会立刻变红。

在 profile 的 `cordis.patch.yml` 里可以用 id 覆盖指向自编译的二进制：

```yaml
- id: deep-pet
  config:
    petBinary: 'E:\path\to\dsh-DeepPet\pet\src-tauri\target\release\dsh-deep-pet.exe'
```

- `assets/立绘/跑步/跑步_01~08.png`：8 帧跑步动画（朝左），384×512 RGBA。
- `assets/立绘/表情/*.png`：23 张表情立绘，384×512 RGBA（v1 用 `平常` 空闲、`晕` 出错、`坐下` 已终止、`寻找` 断连；完成改用动画）。
- `assets/动作/*.webm`：动作库（VP9 + alpha），由 `build-animation.mjs` 按 `动作清单.json` 从仓库外的 qtrle 母版生成；`index.json` 供前端查表。
- `assets/立绘/表情.png`、`表情2.png`、`表情3.png`、`跑步.png`：1536×1024 总览大图。**参考用，不在运行时清单里**，不会进二进制。
- `assets/音效/任务完成.mp3`：任务完成音效（2.4 秒）。`任务完成.wav`（1.5 秒）是上一版，保留但不再随包分发。

以上都是**作者态**素材。运行时用的是 `pet/public/` 里由 `build-assets.mjs`
装配出的 WebP 版本，不要手工编辑那个目录。
